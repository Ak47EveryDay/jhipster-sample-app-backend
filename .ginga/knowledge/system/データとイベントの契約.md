## データとイベントの契約
- REST の入出力は JSON。キーはプロパティ名（キャメルケース）。DTO は `service.dto`（`AdminUserDTO`、`UserDTO`、`PasswordChangeDTO`）、VM は `web.rest.vm`（`LoginVM`、`ManagedUserVM`、`KeyAndPasswordVM`）。口座・取引・ラベル・権限はエンティティをそのまま入出力に使う。`Instant` は ISO-8601 文字列で入出力し、遅延読み込みオブジェクトは識別子を出力する（docs/03_詳細設計/01_共通仕様書/【JHipsterサンプルアプリ】DTOマッピング設計書.md）。
- JWT のクレーム契約：`sub`（ログインID）、`auth`（権限名を半角空白連結）、`userId`、`iat`、`exp`。応答は `{ "id_token": ... }`。設定 `spring.security.oauth2.resourceserver.jwt` で `authorities-claim-name: auth`、`authority-prefix: ''`（docs/03_詳細設計/01_共通仕様書/【JHipsterサンプルアプリ】セキュリティ設計書.md、docs/03_詳細設計/01_共通仕様書/【JHipsterサンプルアプリ】DTOマッピング設計書.md）。
- エラー応答は `application/problem+json` の RFC 7807 形式。フィールドは `type`（例 `https://www.jhipster.tech/problem/constraint-violation`）、`title`、`status`、`detail`、`message`（`error.*` キー）、`path`、必要時 `fieldErrors`（`objectName`／`field`／`message`）と `params`。成功時のアラートはヘッダ `X-jhipsterSampleApplicationApp-alert`／`-params`、ページングは `X-Total-Count` と `Link` ヘッダ（docs/03_詳細設計/01_共通仕様書/【JHipsterサンプルアプリ】例外処理設計書.md、docs/03_詳細設計/01_共通仕様書/【JHipsterサンプルアプリ】メッセージ.md）。
- DB はテーブル `jhi_user`／`jhi_authority`／`jhi_user_authority`／`bank_account`／`operation`／`label`／`rel_operation__label`。主キーはシーケンス `sequence_generator`（開始 1050、増分 50）で採番。初期データは `src/main/resources/config/liquibase/data/`、サンプルデータは `src/main/resources/config/liquibase/fake-data/` の CSV（`context="faker"`）（docs/999_標準化/システム知識整理.md）。
- メールは HTML（UTF-8、マルチパートなし）で、テンプレートは `src/main/resources/templates/mail/*.html`。リンクは `jhipster.mail.base-url`（フロントエンドのアドレス）＋キー（docs/03_詳細設計/01_共通仕様書/【JHipsterサンプルアプリ】メール送信設計書.md）。

## 1　本書の位置付け

本書は、リポジトリ `jhipster-sample-app-backend` の内部設計文書の総索引である。

| 項目 | 内容 |
| --- | --- |
| 対象 | Spring Boot 4.1.1、Java 21 のバックエンド（REST API のみ。JHipster 9.4.0 で生成したサンプルアプリケーションを切り出したもの） |
| 記載の根拠 | 本リポジトリの現在のコード（`src/main/`、`src/test/`、`pom.xml`）。コードにない機能、インターフェース、テーブル、処理は記載していない |
| 文体 | 常体。コードの識別子（クラス名、メソッド名、パス、キー）は原文のままバッククォートで囲んで記述する |
| 範囲外 | 命名規則、開発手順、チェックリストなどの規約に関する文書（`docs/999_標準化/` を参照）。フロントエンドの設計 |

各設計書は「後続の開発者が文書を読んで、対応するコードを見つけて、その挙動を理解できる」ことを目安に、リポジトリルートからの相対パス、クラス名、メソッド名、エンドポイント、テーブル名を記載している。

## 2　システム名称について

ファイル名と文書名には、すべて接頭辞 **【JHipsterサンプルアプリ】** を付ける。

| 項目 | 内容 |
| --- | --- |
| 採用した名称 | JHipsterサンプルアプリ |
| 名称の由来 | リポジトリ名 `jhipster-sample-app-backend` と、アプリケーション名 `jhipsterSampleApplication`（設定 `spring.application.name`）に対応させた名称である |
| 適用範囲 | 全ファイル名、各設計書のタイトル、セクション先頭の「サブシステム名(ID)」欄 |
| 機能ID | REST のリソースクラス名（例 `AuthenticateController`）、またはサービスクラス名 |

参照プロジェクトは複数のサブシステムを「【サブシステム名】」の接頭辞で区別している。本リポジトリは単一のシステムであり、接頭辞で区別する必要はない。ただし、ファイル名の付け方とセクション構成を参照プロジェクトの習慣に合わせるため、統一の接頭辞を付けることとした。

## 4　参照プロジェクトの分類との対応

参照プロジェクトの分類と文書の種類のうち、本リポジトリに該当するものは同じ名前を使う。該当しないものは「該当なし」とし、空のディレクトリは作成していない。

| 参照プロジェクトの分類・文書 | 本リポジトリでの扱い | 理由・備考 |
| --- | --- | --- |
| 01_共通仕様書 | あり | 同じ分類名を使う。本リポジトリ固有の設計書を追加している |
| 　アプリケーション設定情報 | あり | プロファイル別の設定キーとして記載 |
| 　キー・ロール一覧 | あり | KEY_NAME を REST のエンドポイントとして、権限との対応を記載 |
| 　コードテーブル | あり | 権限コードのみ。他にコード値をテーブルで持つ項目はない |
| 　メッセージ | あり | メッセージリソースに加えて、エラー応答とアラートのメッセージキーを記載 |
| 　ユーザ定義チェックValidate | あり | コードで実装したチェックのほか、アノテーションによる標準のチェックの一覧を併記 |
| 　共通Utilクラス | あり |  |
| 　共通変数一覧 | **該当なし** | 画面や帳票で共有する変数に相当する仕組みがない。設定値は「アプリケーション設定情報」、定数は「定数一覧」に記載 |
| 　定数一覧 | あり |  |
| 02_機能別仕様書 | あり | 同じ分類名を使う。機能ごとにディレクトリを作る |
| 　コントローラ一覧 | あり | REST のリソースクラスの一覧として記載 |
| 　サービス詳細設計書 | あり | REST リソースクラスとサービスクラスの処理を合わせて記載 |
| 　SERVICE_DTO設計書 | あり | `service.dto` の DTO と `web.rest.vm` の VM を記載。DTO や VM を使わない機能では作成していない |
| 　LOGIC_DTO設計書 | **該当なし** | ロジック層がない |
| 　ロジック詳細設計書 | **該当なし** | ロジック層がない。業務処理はサービス詳細設計書に記載 |
| 03_DaoDto仕様書 | **該当なし** | DAO の入出力 DTO に相当するクラスがない（リポジトリはエンティティをそのまま入出力とする）。DTO とエンティティの対応は「DTOマッピング設計書」に記載 |
| 04_SQLClient仕様書 | **該当なし** | SQL を記述する独立した層がない（Spring Data JPA のリポジトリが担う）。代わりに「06_リポジトリ仕様書」を作成 |
| 05_TblDto仕様書 | あり | エンティティがテーブルとのマッピングを担う。ファイル名の形式も同じにする |
| （対応なし） | 06_リポジトリ仕様書 | 新設。リポジトリのメソッド、検索条件、JPQL を記載 |
| （対応なし） | 07_DBマイグレーション仕様書 | 新設。Liquibase の変更セットと初期データを記載 |
| asset（処理フロー図の画像） | 作成しない | 図は Markdown 内の Mermaid として記載 |

番号の 03、04 は空き番号である。参照プロジェクトの分類との対応が分かるように、番号は詰めない。

## 5　用語の対応

参照プロジェクトの用語と、本リポジトリで対応するものの関係は次のとおりである。

| 参照プロジェクトの用語 | 本リポジトリでの対応 | 備考 |
| --- | --- | --- |
| コントローラ | リソースクラス（`@RestController` が付いたクラス。`web.rest` パッケージ） | 文書名は「コントローラ一覧」のまま使う |
| TblDto | エンティティ（`domain` パッケージ） | テーブルと 1 対 1 で対応する点が同じ |
| Dao、SqlClient | リポジトリ（`repository` パッケージ） |  |
| Service | サービスクラス、および REST リソースクラス | サービスクラスを持たない機能では、リソースクラスが業務処理を担う |
| DTO | `service.dto` の DTO と `web.rest.vm` の VM | 文書名は「SERVICE_DTO設計書」のまま使う |
| サブシステム名 | JHipsterサンプルアプリ |  |
| 機能ID | リソースクラス名、またはサービスクラス名 |  |

本リポジトリ独自の用語は次のとおりである。

| 用語 | 意味 |
| --- | --- |
| リソースクラス | REST のエンドポイントを定義するクラス |
| 認証済み | 有効な JWT を持つユーザであれば権限を問わないこと |
| URL による認可 | セキュリティフィルタチェインでパスごとに判定する認可 |
| メソッドセキュリティ | リソースクラスのメソッドに付与した `@PreAuthorize` による認可 |
| 未有効化ユーザ | ユーザ登録後に有効化（アクティベーション）が完了していないユーザ |

## 6　記載の約束

| No | 項目 | 約束 |
| --- | --- | --- |
| 1 | ファイルパス | リポジトリルートからの相対パスで記載する |
| 2 | 改版履歴 | 各文書の先頭に置く。担当者と確認者は空欄とする |
| 3 | セクション | 「02_機能別仕様書」のサービス詳細設計書は、各セクションの先頭に「サブシステム名(ID)」「機能ID」「機能日本語名」「処理名」「処理種別」の表を置く |
| 4 | エラー応答の `type` | URI の末尾の要素（`problem-with-message`、`constraint-violation`、`invalid-password`、`email-already-used`、`login-already-used`）で略記する |
| 5 | 根拠の表示 | エラー一覧の「根拠」欄には、確認したテストのメソッド名、または「コード（～）」「コードからの導出（～）」を記載する |
| 6 | 処理フロー図 | Mermaid のフローチャートまたはシーケンス図として、Markdown 内に記載する |
| 7 | 継承したメソッド | リポジトリの `save`、`delete`、`findById`、`findAll`、`existsById`、`deleteById`、`flush` は `JpaRepository` から継承したメソッドであり、リポジトリのインターフェースには宣言がない |
| 8 | フィールドの表記 | 「クラス名#フィールド名」は、そのクラスのフィールドを表す |
| 9 | 実行時に組み立てるキー | `error.{エラーキー}`、`error.http.{ステータス}`、`{エンティティ名}.created` 等は実行時に組み立てられるため、コードの中に完全な文字列としては現れない。構成要素（エラーキー、エンティティ名、ステータス）で確認する |
| 10 | 依存関係のクラス | Spring、Hibernate などの依存関係のクラスとメソッド（`PasswordEncoder#matches`、`JpaRepository` 等）は、本リポジトリのソースコードには定義がない |
| 11 | 表のセル | セルの末尾には「。」を付けない（「処理概要」の「・」の行を除く）。セル内に複数の文を書くときは、文と文の間の「。」は付ける |
| 12 | 例外と戻り値 | 例外は「スローする」、値は「返す」と書く |

「根拠」の種類の意味は次のとおりである。

| 種類 | 意味 |
| --- | --- |
| テストのメソッド名 | 本リポジトリの統合テストが、そのステータスや応答を確認している |
| コード（～） | コードの記述から直接読み取れる（アノテーション、設定値、分岐など） |
| コードからの導出（～） | コードの規則をたどって導いた結論。HTTP レベルで確認するテストはない |

## 7　未確認事項と留意事項

文書化にあたり、コードからは確定できなかった点と、コードから読み取れる留意点を記載する。

| No | 項目 | 内容 | 記載箇所 |
| --- | --- | --- | --- |
| 1 | パス変数の形式チェック | `UserResource` のパス変数 `login` に `@Pattern` を付与しているが、クラスに `@Validated` がない。チェックがフレームワークのメソッドバリデーションで実際に実行されるかは未確認 | サービス詳細設計書_ユーザ管理 |
| 2 | 未有効化ユーザのログイン | `UserNotActivatedException` は 500 になる（コードからの導出）。HTTP レベルで確認するテストはない | サービス詳細設計書_ログイン認証、例外処理設計書 |
| 3 | 権限不足の応答 | `AuthorityResource` で `ROLE_ADMIN` 以外のユーザが呼び出した場合は 403 の Problem Details になる（コードからの導出） | サービス詳細設計書_権限管理 |
| 4 | 外部キー制約に反する削除 | 参照されている権限、口座、ラベルの削除は 500 になる（コードからの導出） | 各サービス詳細設計書 |
| 5 | 公開ユーザ情報検索の認可 | クラスのコメントは「誰でも呼び出せる」と記すが、`SecurityConfiguration` では認証済みが必要 | サービス詳細設計書_公開ユーザ情報検索、セキュリティ設計書 |
| 6 | 未使用の定義 | 主コードからの呼び出し元がないもの：`UserMapper`、`UserService#getAuthorities`、`BankAccountRepository#findByUserIsCurrentUser`、`SecurityMetersService#trackTokenUnsupported`、`MailService#sendEmail`、設定 `jhipster.http.cache.timeToLiveInDays` | 各設計書 |
| 7 | ライブラリの挙動 | JHipster ライブラリ（`HeaderUtil`、`PaginationUtil`、`ResponseUtil`、`RandomUtil`、`PrefixedKeyGenerator`、`SpringLiquibaseUtil`）と Spring Security（401 と 403 の処理クラス）の挙動は、依存関係の JAR ファイルを確認して記載した。その他のライブラリのクラスは、本リポジトリでの使われ方だけを記載した | 共通Utilクラス、セキュリティ設計書など |
| 8 | メッセージの文言 | エラー応答とアラートのメッセージキー（`error.*`、`*.created` 等）に対する文言のリソースは、本リポジトリにはない | メッセージ |
| 9 | 図 | 処理フロー図の画像は作成していない。主要な処理だけ Mermaid で図示している | 各設計書 |
| 10 | 初期ユーザのパスワード | 初期データのハッシュ値を照合して平文を確認した（開発・検証用） | 初期データ・サンプルデータ設計書 |

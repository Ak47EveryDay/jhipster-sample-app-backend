# 開発チェックリスト

> **位置づけ**：機能の追加や変更を始める前、コードを書いている間、提出する前の 3 つの段階で確認する項目をまとめたものである。各項目の根拠は、このディレクトリの各ドキュメントとコードである。現状のコード・テスト・ビルド設定から読み取れた事実だけを挙げており、将来の方針は含めていない。
> 使い方：A（着手前）→ B（コーディング）→ C（マイグレーションと設定）→ D（テスト）→ E（提出前）の順に確認する。各表の「根拠」の欄に、確認できる場所を記す。
> パスは `src/main/java/io/github/jhipster/sample/` 基準で表記する（「テストソースの」とあるものは `src/test/java/io/github/jhipster/sample/` 基準）。

---

## A. 着手前

| No | 確認項目 | 合格基準 | 根拠 |
|---|---|---|---|
| A-1 | エンドポイントのパス | `/api/...` の下に置く（管理者向けは `/api/admin/...`）。`/api` と `/management` のいずれにも入らないパスは使わない | `config/SecurityConfiguration.java`、`REST・エンティティ追加手順.md` の 2.1 節 |
| A-2 | アクセス制御の要否 | 未認証で呼べるようにするか、管理者限定にするかを決める。何もしなければ「認証が必要」になる | `REST・エンティティ追加手順.md` の 5 節、6 節 |
| A-3 | クラスの置き場所 | 新しいクラスのパッケージが、既存のレイヤー（`domain`、`repository`、`service`、`web.rest` など）のいずれかに収まる | `レイヤー別開発ガイド.md` の 2 節 |
| A-4 | 見本の選択 | 同種の既存コードを 1 つ選び、その構成を写す | `REST・エンティティ追加手順.md` の各節 |
| A-5 | DB の変更 | テーブルやカラムを変えるなら、チェンジログを追加する計画を立てる（エンティティを変えただけでは DB は変わらない） | `config/application.yml` の `spring.jpa.hibernate.ddl-auto: none` |
| A-6 | フロントエンドとの整合 | リクエストやレスポンスの形式を変えるなら、別リポジトリのフロントエンドへの影響を確認する | `README.md` |
| A-7 | キャッシュ | エンティティに `@Cache` を付けるなら、`CacheConfiguration` に登録する計画を立てる | `config/CacheConfiguration.java` |

## B. コーディング

| No | 確認項目 | 合格基準 | 根拠 |
|---|---|---|---|
| B-1 | レイヤーの依存方向 | `service` から `web.rest` を参照しない。`domain` と `repository` から上位のレイヤーを参照しない。`config` を参照するのは `Constants` と `ApplicationProperties` だけにする | テストソースの `TechnicalStructureTest.java` |
| B-2 | 依存の注入 | コンストラクタ注入にし、フィールドは `private final` にする | `service/UserService.java`、`web/rest/LabelResource.java` |
| B-3 | トランザクション | エンティティ向けの REST コントローラはクラス単位の `@Transactional(rollbackFor = Exception.class)`、サービスは `@Transactional`（参照のみは `readOnly = true`） | `web/rest/BankAccountResource.java`、`service/UserService.java` |
| B-4 | 入力チェック | 作成と更新は `@Valid @RequestBody` を付ける。エンティティや DTO の項目には Bean Validation の注釈を付ける | `web/rest/LabelResource.java`、`domain/Label.java` |
| B-5 | エラー | 入力チェックの失敗は `BadRequestAlertException` を投げる。サービスレイヤーの業務例外は `service` パッケージに置く | `web/rest/errors/BadRequestAlertException.java`、`service/UsernameAlreadyUsedException.java` |
| B-6 | 例外クラスの取り込み | `EmailAlreadyUsedException` と `InvalidPasswordException` は `service` と `web.rest.errors` の両方にある。`import` するパッケージを確認する | `web/rest/AccountResource.java` の `import` |
| B-7 | 遅延読み込み | レスポンスに含める関連は、リポジトリの `find...WithEagerRelationships` で取得する | `repository/BankAccountRepository.java`、`config/application.yml` の `spring.jpa.open-in-view: false` |
| B-8 | 部分更新 | エンティティに項目を追加したら、`partialUpdate<Entity>` の `updateIfPresent` に追加する | `web/rest/OperationResource.java` の `partialUpdateOperation` |
| B-9 | 機微情報 | パスワードなどの機微な値を `toString` に出さない。`User` の機微な項目には `@JsonIgnore` を付ける | `web/rest/vm/LoginVM.java`、`domain/User.java` |
| B-10 | ログ | REST コントローラのメソッドの先頭に `LOG.debug("REST request to ...")` を置く。値は `{}` のプレースホルダーで渡す | `web/rest/LabelResource.java` |
| B-11 | 名前 | `ネーミング・コーディング規約.md` のとおりに付ける | 同ドキュメント |
| B-12 | Javadoc | REST コントローラのメソッドに `{@code POST  /labels} : ...` の書式で書く | `web/rest/LabelResource.java` の `createLabel` |
| B-13 | Lombok と `record` | 使わない | `pom.xml` |
| B-14 | ユーザーの変更 | ユーザーを保存・削除したら `clearUserCaches` を呼ぶ | `service/UserService.java` |

## C. マイグレーションと設定

| No | 確認項目 | 合格基準 | 根拠 |
|---|---|---|---|
| C-1 | チェンジログの置き場所 | `src/main/resources/config/liquibase/changelog/` に置き、`master.xml` で `<include>` する | `src/main/resources/config/liquibase/master.xml` |
| C-2 | チェンジセットの ID | 既存の形式（`<yyyyMMddHHmmss>-1` など）に合わせる。`author` は `jhipster` にする | `src/main/resources/config/liquibase/changelog/` の既存ファイル |
| C-3 | エンティティとの一致 | `@Table`、`@Column` の名前と型が、チェンジログの定義と一致する | `domain/Label.java` と `20150805124936_added_entity_Label.xml` |
| C-4 | コンテキスト | サンプルデータは `context="faker"` のチェンジセットに置く。`faker` は dev でだけ有効になる | `config/application-dev.yml` の `spring.liquibase.contexts` |
| C-5 | 秘密情報 | `config/application-secret-samples.yml` のサンプル値を、本番用の設定に書かない。`jhipster.security.authentication.jwt.base64-secret` に既定値はない | `config/SecurityJwtConfiguration.java`、`README.md` |
| C-6 | プロファイル間の違い | dev と prod で値が異なる設定（DB、CORS、ログレベル、`base-url` など）を確認する | `設定とビルド手順.md` の 8 節 |
| C-7 | アプリ固有の設定 | `application.*` の設定は `ApplicationProperties` にフィールドを追加してから YAML に書く（未知のキーはエラーになる） | `config/ApplicationProperties.java` の `ignoreUnknownFields = false` |

## D. テスト

| No | 確認項目 | 合格基準 | 根拠 |
|---|---|---|---|
| D-1 | クラス名 | 単体テストは `<対象クラス>Test`、統合テストは `<対象クラス>IT` にする。補助クラスの名前に `IT` を含めない | `pom.xml` の surefire と failsafe のパターン |
| D-2 | 統合テストの注釈 | `@IntegrationTest` と `@AutoConfigureMockMvc` を付ける。認証が必要なエンドポイントには `@WithMockUser` を、管理者限定には `@WithMockUser(authorities = AuthoritiesConstants.ADMIN)` を付ける | テストソースの `web/rest/BankAccountResourceIT.java`、`web/rest/UserResourceIT.java` |
| D-3 | 成功と失敗の両方 | 正常系のステータスに加えて、入力チェックの失敗と、存在しない ID に対する異常系を書く | テストソースの `web/rest/BankAccountResourceIT.java` の `checkNameIsRequired`、`getNonExistingBankAccount` |
| D-4 | DB の後始末 | `@Transactional` または `@AfterEach` でデータを戻す。件数の前後を確認する | テストソースの `web/rest/AccountResourceIT.java` の `checkUsers` |
| D-5 | アクセス制御のテスト | 未認証で呼べないことを検証するテストケースがあるかを確認する | テストソースの `web/rest/AccountResourceIT.java` の `testGetUnknownAccount`、`config/ApiOnlyIT.java` |
| D-6 | 実行 | CI と同じ `./mvnw -Pprod verify` が成功する（PostgreSQL のコンテナーを使うため Docker が必要）。H2 で確かめるときは `./mvnw verify` | `.github/workflows/github-actions.yml`、`README.md` の「Building and testing」 |

## F. よくあるはまり方

| 症状 | 原因 | 確認する場所 |
|---|---|---|
| 新しいエンドポイントが `401` や `403` になる | パスが `/api`、`/management` のいずれにも入らない。または `permitAll()` のルールが `/api/**` の `authenticated()` より後ろにある | `config/SecurityConfiguration.java` |
| 管理者向けのエンドポイントを一般ユーザーが呼べる | `@PreAuthorize` を付けていない、またはパスが `/api/admin/` の下にない | `web/rest/UserResource.java`、`web/rest/AuthorityResource.java` |
| エンティティを変えたのに DB が変わらない | チェンジログを追加していない | `REST・エンティティ追加手順.md` の 8 節 |
| PATCH で新しい項目を更新できない | `partialUpdate<Entity>` の `updateIfPresent` に項目を追加していない | `web/rest/BankAccountResource.java` の `partialUpdateBankAccount` |
| レスポンスに関連が含まれない | 関連は遅延読み込みで、OSIV は無効（`spring.jpa.open-in-view: false`）。`find...WithEagerRelationships` を使わずに取得している | `repository/BankAccountRepository.java`、`config/application.yml` |
| 起動時に JWT の秘密鍵のエラーで止まる | `jhipster.security.authentication.jwt.base64-secret` がない（prod はサンプル値を読み込まない） | `config/SecurityJwtConfiguration.java`、`README.md` の「Production」 |
| 単体テストを書いたのに実行されない | クラス名に `IT` が含まれている | `pom.xml` の surefire の `<excludes>` |
| 統合テストが DB の接続で失敗する | `-Pprod` で Docker が使えない。または `test` と `testdev`、`testprod` の組み合わせが正しくない | `README.md` の「Requirements」、`pom.xml` の `profile.test` |
| prod で API ドキュメントが見えない | api-docs プロファイルが有効になっていない。または `ROLE_ADMIN` がない | `config/application.yml`、`config/SecurityConfiguration.java` |
| メールのリンクが正しいアドレスにならない | `jhipster.mail.base-url` がフロントエンドのアドレスになっていない | `config/application-prod.yml`、`README.md` |

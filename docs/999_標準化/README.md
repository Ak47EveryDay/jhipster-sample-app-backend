## 2. 推奨する読み順

1. [システム知識整理.md](./システム知識整理.md) で全体像をつかむ。
2. [主要処理フロー.md](./主要処理フロー.md) の「認証付きリクエスト」と「エラーからエラー応答まで」を読み、リクエストの通り道を理解する。
3. [レイヤー別開発ガイド.md](./レイヤー別開発ガイド.md) と [ネーミング・コーディング規約.md](./ネーミング・コーディング規約.md) を読んでからコードを書く。
4. 機能を追加するときは [REST・エンティティ追加手順.md](./REST・エンティティ追加手順.md) の手順に沿って進め、[テスト作成ガイド.md](./テスト作成ガイド.md) に従ってテストを書く。
5. 提出前に [開発チェックリスト.md](./開発チェックリスト.md) を確認する。

## 3. 表記について

- Java ソースのパスは、特記がない限り `src/main/java/io/github/jhipster/sample/` 基準で表記する（例：`web/rest/BankAccountResource.java`）。テストソースは `src/test/java/io/github/jhipster/sample/` 基準とし、「テストソースの」と明示する。
- 設定ファイルのパスは `src/main/resources/` 基準で表記する（例：`config/application-dev.yml`）。テスト用の設定は `src/test/resources/` 基準とする。`pom.xml`、`README.md`、`.github/workflows/github-actions.yml` はリポジトリルート基準のパスである。
- クラス名・メソッド名・設定キーなどのコード上の識別子はバッククォートで囲む。Javadoc やログメッセージなど、コードに書かれた英語はそのまま引用する。
- 「プロファイル」は、Spring のものを「Spring プロファイル」、Maven のものを「Maven プロファイル」と書き分ける。単に「プロファイル」と書いた場合は Spring プロファイルを指す。
- 日本語の文中のコロンは全角「：」を使い、直後にスペースを置かない。コードブロック（図を含む）とバッククォートで囲んだ部分では半角「:」を使う。
- 規則としては、本リポジトリのコード・テスト・ビルド設定から読み取れた事実だけを記載した。将来の方針や、コードからは確認できない意図は書いていない。

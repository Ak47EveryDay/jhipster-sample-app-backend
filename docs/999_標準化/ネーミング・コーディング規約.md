# ネーミング・コーディング規約

> **位置づけ**：本リポジトリのコード、レイヤー間の依存を検証するテスト、静的検査の設定、テストコードから読み取った「実際に守られている規則」をまとめたものである。元にした社内規約書などはない。ここに書いていない種類の名前を付けるときは、同じ種類の既存コードに合わせること。
> パスは `src/main/java/io/github/jhipster/sample/` 基準で表記する。レイヤーごとの構造は `レイヤー別開発ガイド.md`、テストの書き方は `テスト作成ガイド.md` を参照。

---

## 1. パッケージ名

パッケージは役割（レイヤー）ごとに分け、ベースパッケージ `io.github.jhipster.sample` の直下に置く。サブパッケージを持つのは `aop.logging`、`service.dto`、`service.mapper`、`web.rest.errors`、`web.rest.vm` である。エンティティ名などでパッケージを分けることはしない。担当の一覧は `レイヤー別開発ガイド.md` の 2 節を参照。

## 2. クラス名

| 種類 | 形式 | 例 | 置き場所 |
|---|---|---|---|
| 起動クラス | `<アプリ名>App` | `JhipsterSampleApplicationApp` | ルート |
| 設定クラス | `<担当>Configuration` | `SecurityConfiguration`、`CacheConfiguration`、`LiquibaseConfiguration` | `config` |
| アプリ固有の設定 | `ApplicationProperties` | `ApplicationProperties` | `config` |
| 定数クラス | `<範囲>Constants` | `Constants`、`AuthoritiesConstants`、`ErrorConstants` | `config`、`security`、`web/rest/errors` |
| ユーティリティクラス | `<担当>Utils` | `SecurityUtils` | `security` |
| Logback の変換器 | `<目的>Converter` | `CRLFLogConverter` | `config` |
| エンティティ | 単数形の名詞 | `BankAccount`、`Label`、`Operation`、`User`、`Authority` | `domain` |
| エンティティの基底クラス | `Abstract<役割>Entity` | `AbstractAuditingEntity` | `domain` |
| リポジトリ | `<エンティティ>Repository` | `BankAccountRepository` | `repository` |
| リポジトリのフラグメント | `<エンティティ>RepositoryWithBagRelationships` と、その実装 `...WithBagRelationshipsImpl` | `OperationRepositoryWithBagRelationships`、`OperationRepositoryWithBagRelationshipsImpl` | `repository` |
| サービス | `<担当>Service` | `UserService`、`MailService` | `service` |
| サービスレイヤーの業務例外 | `<状態>Exception` | `EmailAlreadyUsedException`、`InvalidPasswordException`、`UsernameAlreadyUsedException` | `service` |
| DTO | `<内容>DTO` | `AdminUserDTO`、`UserDTO`、`PasswordChangeDTO` | `service.dto` |
| マッパー | `<エンティティ>Mapper` | `UserMapper` | `service.mapper` |
| VM | `<内容>VM` | `LoginVM`、`ManagedUserVM`、`KeyAndPasswordVM` | `web.rest.vm` |
| REST コントローラ | `<エンティティ>Resource`、`<担当>Resource`、`<担当>Controller` | `BankAccountResource`、`AccountResource`、`AuthenticateController` | `web.rest` |
| エラー応答のための例外 | `<状態>Exception` | `BadRequestAlertException`、`LoginAlreadyUsedException` | `web.rest.errors` |
| エラー応答の要素 | `<内容>VM` | `FieldErrorVM` | `web.rest.errors` |
| コントローラアドバイス | `<目的>Translator` | `ExceptionTranslator` | `web.rest.errors` |
| ログ出力の AOP | `<目的>Aspect` | `LoggingAspect` | `aop.logging` |
| 監視のサービス | `<目的>MetersService` | `SecurityMetersService` | `management` |
| 認証の支援クラス | `<担当>UserDetailsService`、`<機構>AuditorAware` | `DomainUserDetailsService`、`SpringSecurityAuditorAware` | `security` |

- インターフェースと実装を分けたサービスクラスはない（`ServiceImpl` のような接尾辞は使わない）。
- リポジトリのフラグメントの名前は Spring Data の規則による。フラグメントのインターフェース名に `Impl` を付けたクラスが、その実装として扱われる。
- 例外クラスは `Exception` で終わる。`Error` で終わるクラスはない。

## 3. テーブルとカラムの名前

| 対象 | 規則 | 例 |
|---|---|---|
| テーブル | スネークケース。JHipster のコアテーブルは `jhi_` で始まり、業務のテーブルは接頭辞がない | `jhi_user`、`jhi_authority`、`bank_account`、`label`、`operation` |
| 多対多の結合テーブル | `rel_<テーブルA>__<テーブルB>`（アンダースコア 2 つで区切る） | `rel_operation__label` |
| カラム | スネークケース | `first_name`、`created_date` |
| 外部キーのカラム | `<参照先のエンティティ>_id`。参照先の主キーが `id` 以外のときは `<参照先>_<主キー名>` | `user_id`、`bank_account_id`、`authority_name` |
| 主キーの制約 | `<テーブル名>PK` | `jhi_date_time_wrapperPK` |
| 一意制約 | `ux_<テーブル>_<カラム>` | `ux_user_login` |
| 外部キーの制約 | `fk_<テーブル>__<カラム>`、または `fk_<カラム>` | `fk_bank_account__user_id`、`fk_user_id` |
| シーケンス | スネークケース | `sequence_generator` |

- Java のフィールドはキャメルケースにし、`@Column(name = "...")` でカラム名を明示する。`spring.jpa.hibernate.naming.physical-strategy` は `CamelCaseToUnderscoresNamingStrategy` である（`config/application.yml`）。
- 制約名は `src/main/resources/config/liquibase/` のチェンジログで確認できる。上表の `fk_` の 2 通りの書き方は、どちらも初期スキーマ（`00000000000000_initial_schema.xml`）と業務テーブルのチェンジログに実在する。

## 4. REST のパス

| 対象 | 規則 | 例 |
|---|---|---|
| 先頭 | `/api` | `/api/bank-accounts` |
| エンティティの集約 | ケバブケースの複数形 | `/api/bank-accounts`、`/api/labels`、`/api/operations`、`/api/authorities` |
| 個別のリソース | 集約のパスに `/{id}` を加える。ユーザーは `/{login}` | `/api/bank-accounts/{id}`、`/api/admin/users/{login}` |
| 管理者向け | `/api/admin/` の下に置く | `/api/admin/users` |
| 認証とアカウント | 動詞・名詞をケバブケースで並べる | `/api/authenticate`、`/api/register`、`/api/activate`、`/api/account`、`/api/account/change-password`、`/api/account/reset-password/init`、`/api/account/reset-password/finish` |
| 管理エンドポイント | `/management` | `/management/health`、`/management/info`、`/management/prometheus` |

パスとアクセス制御の関係は `モジュール構成と共通部品.md` の 2 節を参照。

## 5. メソッド名

### 5.1 本体

| 対象 | 規則 | 例 |
|---|---|---|
| エンティティ向け REST コントローラ | `create<Entity>`、`update<Entity>`、`partialUpdate<Entity>`、`getAll<Entity>s`、`get<Entity>`、`delete<Entity>` | `createBankAccount`、`partialUpdateBankAccount`、`getAllBankAccounts` |
| その他の REST コントローラ | 動詞で始める | `registerAccount`、`activateAccount`、`saveAccount`、`changePassword`、`requestPasswordReset`、`finishPasswordReset`、`authorize`、`isAuthenticated` |
| サービス | 動詞で始める。参照のみのメソッドは `get...` | `registerUser`、`requestPasswordReset`、`getAllManagedUsers`、`getUserWithAuthorities` |
| リポジトリ | Spring Data の派生クエリの命名（`findBy...`、`findAllBy...`）。カスタムのクエリは `...WithEagerRelationships`、`...WithToOneRelationships`、`fetchBagRelationships` | `findOneByLogin`、`findAllByActivatedIsFalseAndActivationKeyIsNotNullAndCreatedDateBefore`、`findAllWithEagerRelationships` |
| エンティティのアクセサー | `getXxx`、`setXxx`。値を設定して自身を返すメソッドは `xxx(値)`。関連の操作は `addXxx`、`removeXxx` | `getBalance`、`setBalance`、`balance(BigDecimal)`、`addOperation`、`removeOperation` |
| Bean を定義するメソッド | Bean の役割を表す名詞 | `filterChain`、`passwordEncoder`、`jwtDecoder`、`jwtEncoder`、`taskExecutor`、`corsFilter`、`liquibase` |
| 例外クラスのコンストラクタ | 引数なし（メッセージを内部で固定）、またはメッセージのみ | `new UsernameAlreadyUsedException()`、`new BadRequestAlertException(メッセージ, entityName, errorKey)` |

テストのメソッド名は `テスト作成ガイド.md` の 2 節を参照。

## 6. 変数と定数

| 対象 | 規則 | 例 |
|---|---|---|
| ロガー | `LOG`（`private static final Logger LOG`） | 全クラス |
| その他の定数 | アッパースネークケース | `ENTITY_NAME`、`ALLOWED_ORDERED_PROPERTIES`、`JWT_ALGORITHM`、`USERS_BY_LOGIN_CACHE` |
| 依存を受け取るフィールド | フィールドの型名の先頭を小文字にした名前 | `bankAccountRepository`、`userService`、`mailService`、`userRepository` |
| アプリ名を受け取るフィールド | `applicationName`（`@Value("${jhipster.clientApp.name:jhipsterSampleApplication}")`） | 各 `*Resource`、`ExceptionTranslator` |
| エンティティ名を表す定数 | `ENTITY_NAME`。値は小文字で始まるエンティティ名 | `"bankAccount"`、`"label"`、`"operation"` |
| エラーキー | 小文字のみ | `idexists`、`idnull`、`idinvalid`、`idnotfound` |

## 7. コーディングの作法

| 項目 | 作法 | 根拠 |
|---|---|---|
| 依存の注入 | コンストラクタ注入。フィールドは `private final` | `service/UserService.java`、`web/rest/*Resource.java` |
| Lombok、`record` | 使わない。getter と setter、`toString` は手書き | `pom.xml`、全ソース |
| `var` | 型が明らかな局所変数で使う | `config/AsyncConfiguration.java`、`web/rest/AuthenticateController.java` |
| パターンマッチング | `instanceof` の型パターン、`switch` のパターンを使う（Java 21） | `security/SecurityUtils.java`、テストソースの `web/rest/TestUtil.java` |
| テキストブロック | 複数行のログメッセージや Pointcut 式に使う | `JhipsterSampleApplicationApp.java`、`aop/logging/LoggingAspect.java` |
| `serialVersionUID` | `Serializable` を実装するクラスに `@Serial` を付けて宣言する | 全エンティティ、DTO |
| インポート | `org.springframework.web.bind.annotation.*`、`jakarta.persistence.*`、`jakarta.validation.constraints.*` などの注釈のパッケージはワイルドカードで読み込む。テストでは `Mockito`、`MockMvcRequestBuilders`、`MockMvcResultMatchers`、`assertThat` を static import する | 本体とテストの全ソース |
| Javadoc | 英語で書く。REST コントローラのメソッドは `{@code POST  /bank-accounts} : Create a new bankAccount.` の書式 | `web/rest/BankAccountResource.java` |
| 手書きの `toString` | `// prettier-ignore` を付ける | 各エンティティ、DTO、VM |
| ユーティリティクラス | `final` なクラスにし、`private` のコンストラクタを宣言する | `security/SecurityUtils.java`、`web/rest/errors/ErrorConstants.java` |
| ログのメッセージ | 英語。値は `{}` のプレースホルダーで渡し、文字列を連結しない。例外は最後の引数に渡す | `service/MailService.java` の `LOG.warn(..., e)` |
| REST コントローラのログ | メソッドの先頭に `LOG.debug("REST request to <処理> <対象> : {}", ...)` を置く | 各 `*Resource` |
| Bean 定義での `@Value` | 設定キーには既定値を付けることがある（`${jhipster.clientApp.name:jhipsterSampleApplication}`）。JWT の秘密鍵には既定値がない | 各 `*Resource`、`config/SecurityJwtConfiguration.java` |
| `@PreAuthorize` の式 | 2 通りの書き方が混在している。`UserResource` は `@PreAuthorize("hasAuthority(\"" + AuthoritiesConstants.ADMIN + "\")")`、`AuthorityResource` は `@PreAuthorize("hasAnyAuthority('ROLE_ADMIN')")` | 両クラス |
| メッセージの外部化 | メールの件名と本文は `src/main/resources/i18n/messages*.properties` に置く。REST のエラーメッセージは英語の文字列リテラルのままである | `service/MailService.java`、`web/rest/errors/*` |

## 8. 静的検査とビルド時の検証

| 仕組み | 設定場所 | 内容 |
|---|---|---|
| Checkstyle | `checkstyle.xml`、`pom.xml` の `maven-checkstyle-plugin` | `NoHttpCheck`（`io.spring.nohttp`）のみ。対象は `pom.xml` と `README.md` で、`http://` の記述を検出する。依存ライブラリ nohttp（0.0.11）の既定の許可リストに一致する URL（`http://localhost...`、`http://127.0.0.1...` など）は検出されない。`// CHECKSTYLE:OFF` と `// CHECKSTYLE:ON` で抑止できる |
| Spotless | `pom.xml` の `spotless-maven-plugin` | `process-sources` フェーズで `apply` を実行する。ただし `<java>` の中に整形の手順がなく（`<removeUnusedImports/>` はコメントアウトされている）、整形の内容は定義されていない |
| Modernizer | `pom.xml` の `modernizer-maven-plugin` | `package` フェーズで実行。`javaVersion` は 21 |
| Enforcer | `pom.xml` の `maven-enforcer-plugin` | Maven は 3.2.5 以上、JDK は 21 または 25 を要求する。依存関係のバージョンの収束（`DependencyConvergence`）は `fail=false` で警告にとどめる |
| ArchUnit | テストソースの `TechnicalStructureTest.java` | レイヤー間の依存方向を検証する。単体テストとして実行される |
| JaCoCo | `pom.xml` の `jacoco-maven-plugin` | 単体テストと統合テストのカバレッジを計測する |
| SonarQube | `sonar-project.properties` | プロジェクトキーは `jhipsterSampleApplication`。カバレッジは `target/site/**/jacoco*.xml` を参照する。一部のルールを除外している |
| エディターの書式 | `.editorconfig` | Java は 4 スペース、それ以外は 2 スペースのインデント。UTF-8、LF、末尾に改行 |

- CI では `./mvnw -ntp --batch-mode -Pprod verify` を実行し、上記の検査とテストをまとめて実行している（`.github/workflows/github-actions.yml`）。

## 9. JHipster のジェネレーター用のコメント

コードには `jhipster-needle-...` という形式のコメントが残っている。これは JHipster がコードを再生成するときに、コードを挿入する位置を示す印である。本リポジトリは再生成できない（`README.md`）が、コメントは削除されていない。

| コメント | 位置 |
|---|---|
| `// jhipster-needle-entity-add-field`、`// jhipster-needle-entity-add-getters-setters` | エンティティのクラス内 |
| `// jhipster-needle-ehcache-add-entry` | `config/CacheConfiguration.java` |
| `// jhipster-needle-application-properties-property` など | `config/ApplicationProperties.java` |
| `# jhipster-needle-add-application-yaml-document` | `config/application.yml` |
| `<!-- jhipster-needle-logback-add-log -->` | `logback-spring.xml` |
| `<!-- jhipster-needle-liquibase-add-changelog -->` など | `config/liquibase/master.xml` と各チェンジログ |

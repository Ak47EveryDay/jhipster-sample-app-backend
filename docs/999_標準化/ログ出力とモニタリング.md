# ログ出力とモニタリング

> **位置づけ**：ログの出力方法（Logback の設定、改行混入の対策、AOP によるログ、コードでの書き方、機微情報の扱い）と、監視（Actuator の設定とメトリクス）をまとめたものである。プロファイルごとの設定値の対比は `設定とビルド手順.md` を参照。
> パスは `src/main/java/io/github/jhipster/sample/` 基準、設定ファイルは `src/main/resources/` 基準で表記する。テストソースのファイルには「テストソースの」と明示する。

---

## 1. ロギングの構成

| 要素 | 場所 | 役割 |
|---|---|---|
| ログの API | SLF4J（`org.slf4j.Logger`） | コードは `LoggerFactory.getLogger(<クラス>.class)` でロガーを取得する |
| ログの実装 | Logback | `pom.xml` の依存関係には Logback の名前は直接現れない。`config/LoggingConfiguration.java` と `config/CRLFLogConverter.java` が Logback のクラス（`ch.qos.logback.*`）を使っている |
| 本体のログ設定 | `logback-spring.xml` | コンソールへの出力、ロガーごとのレベル、`crlf` の変換規則 |
| テストのログ設定 | テストソース側の `src/test/resources/logback.xml` | Spring Boot の `base.xml` を取り込み、ロガーごとのレベルを定める |
| 実行時に追加される出力先 | `config/LoggingConfiguration.java` | JSON 形式のコンソール出力と Logstash への転送を、設定に応じて追加する |
| AOP によるログ | `aop/logging/LoggingAspect.java` | dev だけで、サービス・リポジトリ・REST コントローラのメソッドの入出力と例外を記録する |
| 改行混入の対策 | `config/CRLFLogConverter.java` | ログのメッセージ中の改行とタブを置き換える |
| ログの内容を確かめるテスト | テストソースの `aop/logging/LoggingAspectTest.java`、`config/CRLFLogConverterTest.java` | AOP ログと変換規則の出力を検証する |

## 2. `logback-spring.xml` の内容

| 要素 | 内容 |
|---|---|
| 変換規則 | `<conversionRule conversionWord="crlf" converterClass="io.github.jhipster.sample.config.CRLFLogConverter" />` |
| コンソールのパターン | `CONSOLE_LOG_PATTERN`。日時、レベル、プロセス ID、スレッド、ロガー名（最大 40 文字）、メッセージ（`%crlf(%m){red}`）の順。色は `%clr(...)` で付ける |
| 取り込んでいる定義 | Spring Boot の `defaults.xml` と `console-appender.xml` |
| ファイルへの出力 | コメントアウトされている。`file-appender.xml` と `ASYNC` アペンダーの例がコメントとして残っている。現状はコンソールだけに出力する |
| アプリのロガー | `<logger name="io.github.jhipster.sample" level="INFO"/>` |
| フレームワークのロガー | `org.springframework`、`org.springframework.web`、`org.springframework.security`、`org.hibernate`、`org.ehcache`、`com.zaxxer`、`liquibase` などを `WARN` にする |
| root のレベル | `<springProperty name="log.level" source="logging.level.root" defaultValue="INFO" />` で、設定の `logging.level.root` を読み込む |
| その他 | Logback 自身の状態出力を止め、JUL のレベルを Logback にそろえる |

上書きの関係は次のとおりである。

| プロファイル | `logging.level.ROOT` | `logging.level.tech.jhipster` | その他 |
|---|---|---|---|
| dev | `DEBUG` | `DEBUG` | `org.hibernate.SQL: DEBUG`、`io.github.jhipster.sample: DEBUG` |
| prod | `INFO` | `INFO` | `io.github.jhipster.sample: INFO` |

- 実行中は `jhipster.logging.use-json-format` と `jhipster.logging.logstash.enabled` の値に応じて、`config/LoggingConfiguration.java` が JSON のコンソールアペンダーと Logstash の TCP アペンダーを追加する。カスタムフィールドは `app_name`（`spring.application.name`）と `app_port`（`server.port`）。現状、どのプロファイルでもこの 2 つは `false` である（`config/application-dev.yml`、`config/application-prod.yml`）。

## 3. 改行混入の対策（`CRLFLogConverter`）

ログのメッセージに改行が含まれていると、攻撃者が送った値でログの行を偽装できる。`CRLFLogConverter` はこれを防ぐための Logback の変換器である。

| 項目 | 内容 | コード上の位置 |
|---|---|---|
| 置き換える対象 | メッセージ中の `\n`、`\r`、`\t` | `transform` の `in.replaceAll("[\n\r\t]", replacement)` |
| 置き換えた結果 | `_`。オプションで色を指定すれば、その色の `_`（`logback-spring.xml` では `{red}`） | `transform` |
| 置き換えない場合 1 | ログイベントの先頭のマーカーが `CRLF_SAFE_MARKER`（`CRLF_SAFE`）を含むとき | `transform`、`CRLF_SAFE_MARKER` |
| 置き換えない場合 2 | ロガー名が `SAFE_LOGS`（`org.hibernate`、`org.springframework.boot.autoconfigure`、`org.springframework.boot.diagnostics`）のいずれかで始まるとき | `isLoggerSafe`、`SAFE_LOGS` |

- `CRLF_SAFE_MARKER` を使っているのは `JhipsterSampleApplicationApp#logApplicationStartup` の起動時のバナーである（複数行のメッセージを出すため）。
- 通常のログでこのマーカーを使う必要はない。

## 4. AOP によるログ（`LoggingAspect`）

| 項目 | 内容 | コード上の位置 |
|---|---|---|
| 有効になる条件 | dev プロファイルのときだけ Bean になる（`config/LoggingAspectConfiguration.java` の `@Profile`） | `LoggingAspectConfiguration#loggingAspect` |
| 対象 | `@Repository`、`@Service`、`@RestController` のいずれかが付いたクラスで、パッケージが `repository`、`service`、`web.rest` のいずれかの配下にあるもの | `springBeanPointcut`、`applicationPackagePointcut` |
| メソッドの入出力 | DEBUG で `Enter: <メソッド>() with argument[s] = <引数>` と `Exit: <メソッド>() with result = <戻り値>` を出す | `logAround` |
| `IllegalArgumentException` | ERROR で `Illegal argument: <引数> in <メソッド>()` を出し、例外はそのまま送出する | `logAround`、`logIllegalArgument` |
| 例外の送出 | ERROR で出す。dev のときは原因と例外のメッセージとスタックトレースを、dev 以外のときは原因のみを出す | `logAfterThrowing`、`logException` |

- `logAround` は引数を `Arrays.toString(joinPoint.getArgs())` で出力するため、引数のオブジェクトの `toString` の内容がそのままログに出る。機微情報を含むオブジェクトを引数にするときは 6 節を参照。
- ログに出るロガー名は、対象メソッドを宣言したクラスの名前である（`logger(JoinPoint)`）。

## 5. コードでのログの出し方

| 作法 | 内容 | 例 |
|---|---|---|
| ロガーの宣言 | `private static final Logger LOG = LoggerFactory.getLogger(<クラス>.class);` | 全クラス |
| メッセージ | 英語で書く。値は `{}` のプレースホルダーで渡し、文字列を連結しない | `LOG.debug("Authenticating {}", login)`（`security/DomainUserDetailsService.java`） |
| 例外 | 最後の引数に例外オブジェクトを渡す | `LOG.warn("Email could not be sent to user '{}'", to, e)`（`service/MailService.java`） |
| REST コントローラ | メソッドの先頭に `LOG.debug("REST request to <処理> <対象> : {}", ...)` を置く | `LOG.debug("REST request to save Label : {}", label)`（`web/rest/LabelResource.java`） |
| 複数行のメッセージ | `CRLFLogConverter.CRLF_SAFE_MARKER` を第 1 引数に渡す | `JhipsterSampleApplicationApp#logApplicationStartup` |

本体で使われているレベルは次のとおりである（`LOG.<レベル>(` の呼び出し箇所の数）。

| レベル | 箇所数 | 使われている場面 | 例 |
|---|---|---|---|
| `debug` | 57 | REST コントローラのメソッドの冒頭。サービス内の処理の詳細 | `LOG.debug("Activated user: {}", user)`（`service/UserService.java`） |
| `info` | 4 | 起動時の通知 | `LOG.info("Web application fully configured")`（`config/WebConfigurer.java`） |
| `warn` | 3 | 処理は続行できるが注意が必要な状況 | `LOG.warn("Password reset requested for non existing mail")`（`web/rest/AccountResource.java`） |
| `error` | 3 | 設定の誤り。分類できないエラー | `LOG.error("Unknown JWT error {}", e.getMessage())`（`config/SecurityJwtConfiguration.java`） |

- dev では `io.github.jhipster.sample` が `DEBUG` なので `debug` のログが出る。prod では `INFO` なので出ない。

## 6. 機微情報とログ

| 対象 | 扱い | 根拠 |
|---|---|---|
| パスワード（`User.password`） | `@JsonIgnore` を付け、`toString` に含めない | `domain/User.java` |
| アクティベーションキー、リセットキー | `@JsonIgnore` を付ける。`toString` には `activationKey` が含まれ、`resetKey` は含まれない | `domain/User.java` |
| ログインのリクエストボディ | `LoginVM.toString()` に `password` を含めない | `web/rest/vm/LoginVM.java` |
| ユーザー登録のリクエストボディ | `ManagedUserVM.toString()` と、その親の `AdminUserDTO.toString()` に `password` を含めない | `web/rest/vm/ManagedUserVM.java`、`service/dto/AdminUserDTO.java` |
| パスワード変更、リセットのリクエストボディ | `PasswordChangeDTO` と `KeyAndPasswordVM` は `toString` を定義しない | `service/dto/PasswordChangeDTO.java`、`web/rest/vm/KeyAndPasswordVM.java` |

- ログの項目をマスクする共通の仕組みは、本リポジトリには用意されていない。機微な値は `toString` に出さないことで対応している。
- dev では `aop/logging/LoggingAspect.java` がサービスのメソッドの引数を DEBUG ログに出す（4 節）。`service/UserService.java` の `registerUser(AdminUserDTO userDTO, String password)`、`changePassword(String currentClearTextPassword, String newPassword)`、`completePasswordReset(String newPassword, String key)` はパスワードを引数に取るため、渡された平文のパスワードが dev のコンソールログに出力される。
- `service/MailService.java#sendEmailSync` は DEBUG でメールの本文（`content`）を出力する。dev ではアカウント有効化やパスワードリセットのメールに含まれるキー付きのリンクがログに出る点に注意する。
- `sonar-project.properties` では、ログに関するルール `javasecurity:S5145` を除外している。

## 7. 監視（Spring Boot Actuator）

### 7.1 設定

設定は `config/application.yml` にある。

| 設定キー | 値 | 内容 |
|---|---|---|
| `management.endpoints.web.base-path` | `/management` | 管理エンドポイントの共通の接頭辞 |
| `management.endpoints.web.exposure.include` | `configprops`、`env`、`health`、`info`、`jhimetrics`、`jhiopenapigroups`、`logfile`、`loggers`、`prometheus`、`threaddump`、`caches`、`liquibase` | HTTP で公開するエンドポイント |
| `management.endpoint.health.show-details` | `when_authorized` | 詳細は権限を持つユーザーにだけ見せる |
| `management.endpoint.health.roles` | `ROLE_ADMIN` | 詳細を見られる権限 |
| `management.endpoint.health.probes.enabled` | `true` | liveness と readiness のグループを有効にする |
| `management.endpoint.health.group.liveness.include` | `livenessState` | |
| `management.endpoint.health.group.readiness.include` | `readinessState`、`db` | DB の確認を含む |
| `management.health.mail.enabled` | `false` | メールの疎通確認は含めない |
| `management.prometheus.metrics.export.enabled` | `true`（prod の YAML では `false`） | Prometheus 形式の出力 |
| `management.prometheus.metrics.export.step` | `60` | 集計の間隔（秒） |
| `management.metrics.enable` | `http`、`jvm`、`logback`、`process`、`system` を `true` | 有効にするメトリクス |
| `management.metrics.distribution.percentiles` | `0, 0.5, 0.75, 0.95, 0.99, 1.0` | |
| `management.metrics.data.repository.autotime.enabled` | `true` | リポジトリのメソッドの計測 |
| `management.info.git.mode` | `full` | git の情報を info に含める |
| `management.info.env.enabled` | `true` | 環境の情報を info に含める |

| エンドポイント | アクセス | 根拠 |
|---|---|---|

| `/management/info` | 未認証で参照できる | 同上 |
| `/management/prometheus` | 未認証で参照できる | 同上 |

### 7.3 ビルド情報と git の情報

| 仕組み | 内容 | 根拠 |
|---|---|---|
| `build-info` | `spring-boot-maven-plugin` の `build-info` ゴールがビルド情報を作り、`BuildProperties` として読める | `pom.xml` の `spring-boot-maven-plugin`、`config/CacheKeyGeneratorConfiguration.java` |
| git の情報 | Maven プロファイル `prod` のときだけ `git-commit-id-maven-plugin` が git の情報を作り、`GitProperties` として読める | `pom.xml` の Maven プロファイル `prod` |
| 両者の利用箇所 | `config/CacheKeyGeneratorConfiguration.java` が `@Autowired(required = false)` で受け取る（なくても動く） | 同上 |

### 7.4 アプリ独自のメトリクス

`management/SecurityMetersService.java` が、JWT の検証に失敗した回数を数える。メトリクス名は `security.authentication.invalid-tokens`、タグは `cause`（`invalid-signature`、`expired`、`unsupported`、`malformed`）である。呼び出すのは `config/SecurityJwtConfiguration.java#jwtDecoder` である（`主要処理フロー.md` の 10 節）。

### 7.5 Prometheus と Grafana

- `src/main/docker/monitoring.yml` に Prometheus（`prom/prometheus:v3.14.0`）と Grafana（`grafana/grafana:13.2.2`）の Compose 定義がある。
- `src/main/docker/prometheus/prometheus.yml` は、`localhost:8080` の `/management/prometheus` を 5 秒間隔で取得する設定である。
- Grafana のデータソースとダッシュボードの設定は `src/main/docker/grafana/provisioning/` にある（ダッシュボードは `dashboards/JVM.json`）。
- `src/main/docker/app.yml` のコンテナーのヘルスチェックは `/management/health` のレスポンスに `"status":"UP"` が含まれるかを確認する。同じファイルで `MANAGEMENT_PROMETHEUS_METRICS_EXPORT_ENABLED=true` を指定して、Prometheus 形式の出力を有効にしている。

# システム知識整理

> **位置づけ**：jhipster-sample-app-backend が「何のシステムで、どう動いているか」を一覧にまとめたものである。レイヤーごとの書き方は `レイヤー別開発ガイド.md`、リクエストの流れは `主要処理フロー.md`、ビルドと設定は `設定とビルド手順.md` を参照。
> パスは `src/main/java/io/github/jhipster/sample/` 基準、設定ファイルは `src/main/resources/` 基準で表記する。

---

## 1. システムの位置づけ

| 項目 | 内容 | 根拠 |
|---|---|---|
| 由来 | JHipster 9.4.0 が生成したサンプルアプリケーション（銀行口座・ラベル・取引を扱う）。モノリスからバックエンドとして切り出したもの | `README.md` |
| 役割 | REST API サーバーのみ。Angular の画面は別リポジトリ（jhipster-sample-app-frontend）にあり、HTTP 経由でのみ連携する | `README.md` |
| 起動クラス | `JhipsterSampleApplicationApp`。`@SpringBootApplication` で `H2ConsoleAutoConfiguration` のみを除外している | `JhipsterSampleApplicationApp.java` |
| ベースパッケージ | `io.github.jhipster.sample` | 全ソース |
| 成果物 | `io.github.jhipster.sample:jhipster-sample-application`（バージョン `0.0.1-SNAPSHOT`、jar） | `pom.xml` |
| JHipster による再生成 | 不可。`.yo-rc.json` と `.jhipster/` は削除済みで、エンティティは `domain/` のコードで定義する | `README.md` の「What changed in the split」 |
| 画面の配信 | 行わない。API パス以外は拒否される（未認証なら `401`、認証済みなら `403`） | `README.md`、テストソースの `config/ApiOnlyIT.java` |

## 3. Spring プロファイルの構成

### 3.1 プロファイルの一覧

| Spring プロファイル | 用途 | 定義場所 |
|---|---|---|
| `dev` | 開発時。H2 のインメモリ DB、デバッグログ、CORS 有効、H2 コンソール有効。プロファイルグループにより `secret-samples` と `api-docs` も同時に有効になる | `config/application-dev.yml`、`config/application.yml` の `spring.profiles.group.dev` |
| `prod` | 本番想定。PostgreSQL、INFO レベルのログ、graceful shutdown、レスポンスの圧縮 | `config/application-prod.yml` |
| `secret-samples` | JWT の秘密鍵と DB ユーザーのサンプル値。開発と CI での利用を想定 | `config/application-secret-samples.yml` |
| `api-docs` | springdoc を有効にする。このプロファイルがないとき `springdoc.api-docs.enabled` は `false` | `config/application.yml` の先頭のドキュメント |
| `tls` | TLS と HTTP/2 を有効にする（自己署名証明書） | `config/application-tls.yml` |
| `no-liquibase` | 起動時の Liquibase 実行を止める | `config/LiquibaseConfiguration.java` |
| `test` | テスト共通の設定 | テストソースの設定 `config/application.yml`（`src/test/resources/`） |
| `testdev` | テスト用の H2 DB | テストソースの設定 `config/application-testdev.yml` |
| `testprod` | テスト用の PostgreSQL（Testcontainers） | テストソースの設定 `config/application-testprod.yml`、テストソースの `config/SqlTestContainersSpringContextCustomizerFactory.java` |

### 3.2 Maven プロファイルとの対応

`pom.xml` の `spring.profiles.active` プロパティの値が、ビルド時に `config/application.yml` の `spring.profiles.active: '@spring.profiles.active@'` に埋め込まれる（`config/**/*.yml` はリソースフィルタリングの対象）。

| Maven プロファイル | 有効になる Spring プロファイル | テスト実行時の `spring.profiles.active` |
|---|---|---|
| 指定なし（`dev` が既定で有効） | `dev`。Maven プロファイル `tls`、`no-liquibase` を重ねたときはそれらも追加 | `test,testdev` |
| `prod` | `prod`。Maven プロファイル `api-docs`、`tls`、`e2e`、`no-liquibase` を重ねたときはそれらも追加 | `test,testprod` |

- プロファイルを指定せずに起動した場合の既定のプロファイルは `dev` である。起動クラスの `main` が `DefaultProfileUtil.addDefaultProfile(app)` を呼び、`spring.profiles.default` に `dev` を設定している（`DefaultProfileUtil` は `jhipster-framework` のクラス）。
- `dev` と `prod` を同時に有効にした場合は、起動時にエラーログが出る（`JhipsterSampleApplicationApp.initApplication`）。
- 各プロファイルで実際に変わる設定値は `設定とビルド手順.md` の「プロファイル別のアプリ設定」を参照。

## 4. API の構成

REST コントローラは 8 クラスで、すべて `web/rest/` に置く。パスの先頭は `/api` である。アクセス制御のルールは `config/SecurityConfiguration.java` の `filterChain` に集約されている。

| クラス | ベースパス | アクセス制御 | 呼び出す先 |
|---|---|---|---|
| `AccountResource` | `/api` | `register`、`activate`、`account/reset-password/init`、`account/reset-password/finish` は未認証で呼べる。`account` と `account/change-password` は認証が必要 | `UserService`、`MailService`、`UserRepository`、`PasswordEncoder` |
| `AuthenticateController` | `/api` | `authenticate`（POST と GET）は未認証で呼べる | `AuthenticationManagerBuilder`、`JwtEncoder` |
| `UserResource` | `/api/admin` | `ROLE_ADMIN` が必要。URL のルール（`/api/admin/**`）と、各メソッドの `@PreAuthorize` の二重で守る | `UserService`、`MailService`、`UserRepository` |
| `AuthorityResource` | `/api/authorities` | URL のルールは「認証が必要」のみ。管理者限定は各メソッドの `@PreAuthorize("hasAnyAuthority('ROLE_ADMIN')")` で実現 | `AuthorityRepository` |
| `PublicUserResource` | `/api` | 認証が必要 | `UserService` |
| `BankAccountResource` | `/api/bank-accounts` | 認証が必要 | `BankAccountRepository` |
| `LabelResource` | `/api/labels` | 認証が必要 | `LabelRepository` |
| `OperationResource` | `/api/operations` | 認証が必要 | `OperationRepository` |

- 口座・ラベル・取引の 3 エンティティ（`BankAccount`、`Label`、`Operation`）は、REST コントローラがリポジトリを直接呼ぶ。サービスクラスを挟まない。
- ユーザー（`User`）は `UserService` を経由する。DTO を挟む理由は `web/rest/UserResource.java` の Javadoc に書かれている。権限（`Authority`）は `UserService` を経由せず、`AuthorityResource` が `AuthorityRepository` を直接呼ぶ。
- `PublicUserResource` の Javadoc には「allowed for anyone」とあるが、`SecurityConfiguration` 上は `/api/**` の「認証が必要」のルールに含まれるため、実際には認証が必要である。

## 5. データモデル

### 5.1 テーブルとエンティティ

| テーブル | エンティティ | 主キー | 関連 | 初期データ |
|---|---|---|---|---|
| `jhi_user` | `User`（`AbstractAuditingEntity` を継承） | `id` | `jhi_user_authority` を通じて `Authority` と多対多 | `config/liquibase/data/user.csv`（`admin`、`user`） |
| `jhi_authority` | `Authority` | `name` | なし | `config/liquibase/data/authority.csv`（`ROLE_ADMIN`、`ROLE_USER`） |
| `jhi_user_authority` | なし（`User.authorities` の結合テーブル） | `user_id` と `authority_name` の複合 | なし | `config/liquibase/data/user_authority.csv` |
| `bank_account` | `BankAccount` | `id` | `user_id` から `jhi_user` へ多対 1。`Operation` を 1 対多で持つ | `config/liquibase/fake-data/bank_account.csv` |
| `label` | `Label` | `id` | `Operation` と多対多 | `config/liquibase/fake-data/label.csv` |
| `operation` | `Operation` | `id` | `bank_account_id` から `bank_account` へ多対 1。`Label` と多対多 | `config/liquibase/fake-data/operation.csv` |
| `rel_operation__label` | なし（`Operation.labels` の結合テーブル） | `operation_id` と `label_id` の複合 | なし | なし |
| `jhi_date_time_wrapper` | `DateTimeWrapper`（テストソースのみ） | `id` | なし | なし |

- 主キーはシーケンス `sequence_generator` から採番する（`00000000000000_initial_schema.xml` の `createSequence`。開始値 1050、増分 50）。エンティティ側は `@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "sequenceGenerator")` で受ける。`Authority` だけが `name` を自然キーにする。
- `fake-data/` の CSV は `context="faker"` のチェンジセットでのみ読み込まれる。`faker` コンテキストを指定するのは dev プロファイルだけである（`spring.liquibase.contexts: dev, faker`）。
- `jhi_date_time_wrapper` を作るチェンジセット（`00000000000002`）は `context="test"` であり、テスト（`HibernateTimeZoneIT`）専用である。

### 5.2 権限

`AuthoritiesConstants` に `ROLE_ADMIN`、`ROLE_USER`、`ROLE_ANONYMOUS` が定義されている。JWT の `auth` クレームに権限名を空白区切りで入れ、`config/application.yml` の `spring.security.oauth2.resourceserver.jwt`（`authority-prefix: ''`、`authorities-claim-name: auth`）で読み取る。

## 6. 実行環境の特徴

| 項目 | 内容 | 根拠 |
|---|---|---|
| ポート | 8080（dev と prod）。テストは 10344 | `config/application-dev.yml`、`config/application-prod.yml`、テスト用設定 |
| H2 コンソール | dev では `http://localhost:8080/h2-console` でアクセスできる。dev のときだけ `/h2-console/**` への未認証アクセスを許可 | `README.md`、`config/WebConfigurer.java`、`config/SecurityConfiguration.java` |
| H2 の TCP サーバー | dev かつ `spring.h2.console.enabled=true` のとき起動。ポートは `server.port` に 10000 を加えた値（8080 なら 18080） | `config/DatabaseConfiguration.java` の `h2TCPServer`、`getValidPortForH2` |
| フロントエンド | 開発時は `http://localhost:9060`。フロントの開発サーバーが `/api`、`/management`、`/v3/api-docs`、`/h2-console` をバックエンドへ転送する | `README.md` |
| CORS | dev では `localhost:9060` などのオリジンを許可。prod では設定がないため無効 | `config/application-dev.yml` の `jhipster.cors`、`README.md` |
| メール | アカウント有効化とパスワードリセットのメールは、リンク先としてフロントエンドのアドレスを使う（`jhipster.mail.base-url`） | `README.md`、`service/MailService.java` |
| 管理エンドポイント | ベースパスは `/management`。`health`、`info`、`prometheus` は未認証で参照でき、残りは `ROLE_ADMIN` が必要 | `config/application.yml`、`config/SecurityConfiguration.java` |
| API ドキュメント | `/v3/api-docs/**` は `ROLE_ADMIN` が必要。api-docs プロファイルがないときは無効 | `config/SecurityConfiguration.java`、`config/application.yml` |

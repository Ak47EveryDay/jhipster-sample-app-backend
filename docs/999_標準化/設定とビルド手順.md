# 設定とビルド手順

> **位置づけ**：Maven の設定（Maven プロファイル、プラグイン、依存関係）、Spring プロファイルごとのアプリ設定、日常の操作（起動、テスト、パッケージ化）、CI をまとめたものである。プロファイルの全体像は `システム知識整理.md` の 3 節、マイグレーションの形式は `REST・エンティティ追加手順.md`、テストの実行のされ方は `テスト作成ガイド.md` を参照。
> 記載したコマンドは、`README.md`、`pom.xml`、`.github/workflows/github-actions.yml` に書かれているものである（2 か所だけ、Maven プラグインの標準の指定方法を補足している）。このドキュメントでビルドやテストは実行していない。
> パスは `src/main/resources/` 基準で表記する。`pom.xml`、`README.md`、`.github/workflows/github-actions.yml`、`.mvn/`、`.devcontainer/` はリポジトリルート基準である。

## 3. Maven プロファイル

| ID | 有効になる条件 | 効果 |
|---|---|---|
| `dev` | 既定で有効（`activeByDefault`） | Spring プロファイルは `dev`（`tls`、`no-liquibase` を重ねたときはそれらも追加）。依存に `spring-boot-devtools`、H2、`testcontainers-postgresql`（provided）を追加。テストは `test,testdev`。テストソースの `DatabaseTestcontainer.java` をコンパイルの対象から除外。Liquibase プラグインの接続先は H2 |
| `docker-compose` | 既定で有効（`activeByDefault`） | 依存に `spring-boot-docker-compose`（optional）を追加 |
| `prod` | `-Pprod` | Spring プロファイルは `prod`（`api-docs`、`tls`、`e2e`、`no-liquibase` を重ねたときはそれらも追加）。依存に `postgresql`、`testcontainers-postgresql`（test）を追加。テストは `test,testprod`。`git-commit-id-maven-plugin` を有効にする。Liquibase プラグインの接続先は PostgreSQL |
| `api-docs` | `-Papi-docs` | Spring プロファイルに `api-docs` を追加 |
| `tls` | `-Ptls` | Spring プロファイルに `tls` を追加 |
| `no-liquibase` | `-Pno-liquibase` | Spring プロファイルに `no-liquibase` を追加 |
| `e2e` | `-Pe2e` | Spring プロファイルに `e2e` を追加。成果物名を `e2e` にする |
| `IDE` | `-PIDE` | 注釈プロセッサ（`hibernate-processor`、`mapstruct-processor`）を依存に追加 |
| `eclipse` | Eclipse（m2e）で作業しているとき（プロパティ `m2e.version`） | m2e 用の設定。ビルドには影響しない |

- `-P` で重ねる例：`./mvnw -Pprod,tls` のように指定する。`prod` 単独では `api-docs` と `secret-samples` は有効にならない（8.1 節を参照）。
- Maven プロファイルと Spring プロファイルは別のものである。対応関係は `システム知識整理.md` の 3.2 節を参照。

| `spring-boot-maven-plugin` | `build-info` と `repackage` | `spring-boot:run` による起動、実行可能な jar の作成、ビルド情報の作成 |

| `properties-maven-plugin` | `initialize` | `sonar-project.properties` を Maven のプロパティとして読み込む |
| `modernizer-maven-plugin` | `package` | 古い API の利用箇所の検出（`javaVersion` は 21） |
| `jib-maven-plugin` | コマンドで実行 | コンテナーイメージの作成（`jib:dockerBuild`） |

| `git-commit-id-maven-plugin` | Maven プロファイル `prod` のとき | git の情報の作成（`GitProperties` として読める） |

- コンテナーイメージの設定（`pom.xml` の `jib-maven-plugin`）：イメージ名は `jhipstersampleapplication:latest`、公開するポートは 8080、入口は `src/main/docker/jib` 配下の `/entrypoint.sh`、実行ユーザーは 1000 である。

## 5. リソースフィルタリングと `spring.profiles.active`

- `pom.xml` の `<resources>` では、`src/main/resources/` のうち `config/**/*.yml` だけを `filtering=true` で処理し、残りのファイルは `config/**/*.yml` を除いてコピーしている。
- `config/application.yml` の `spring.profiles.active: '@spring.profiles.active@'` の `@...@` の部分に、Maven プロパティ `spring.profiles.active` の値が入る。Maven プロファイルを指定しなければ `dev`、`-Pprod` なら `prod` になる。
- `config/application.yml` のコメントにあるように、この値は、コマンドラインで渡す `--spring.profiles.active` か、`JAVA_OPTS` に設定した `-Dspring.profiles.active` で上書きできる。
- テスト用の設定（`src/test/resources/config/application.yml`）は、このフィルタリングの対象外である。

## 10. 日常の操作

| やりたいこと | コマンド | 備考 |
|---|---|---|
| dev で起動する（H2） | `./mvnw` | ポート 8080。画面は別リポジトリのフロントエンド（`http://localhost:9060`）を使う |
| 起動を確認する | ブラウザーで `http://localhost:8080/management/health` | H2 コンソールは `http://localhost:8080/h2-console` |
| 単体テストと統合テストを H2 で実行し、パッケージ化する | `./mvnw verify` | 成果物は `target/*.jar` |
| 統合テストを PostgreSQL のコンテナーで実行し、パッケージ化する | `./mvnw -Pprod verify` | Docker が必要 |
| 本番用の jar を作る | `./mvnw -Pprod clean verify` | |
| 本番用の jar を実行する | `java -jar target/*.jar` | PostgreSQL と JWT の秘密鍵が必要 |
| ローカルで試すために prod を起動する | 起動時の引数に `--spring.profiles.active=prod,secret-samples` | サンプルの秘密鍵を使う。ローカルでの試用に限る |
| Docker イメージを作る | `./mvnw -ntp verify -DskipTests -Pprod jib:dockerBuild` | イメージ名は `jhipstersampleapplication:latest` |
| 個別のテストクラスを実行する | surefire は `-Dtest=<クラス名>`、failsafe は `-Dit.test=<クラス名>` | Maven プラグインの標準の指定方法（`README.md` には記載がない） |
| 負荷試験（Gatling）を実行する | `./mvnw gatling:test` | `pom.xml` の `gatling-maven-plugin` のゴール（`README.md` には記載がない）。シミュレーションは起動中のアプリ（既定は `http://localhost:8080`。システムプロパティ `baseURL` で変更できる）に接続する。先にアプリを起動する。接続先の既定値は `src/test/java/gatling/simulations/BankAccountGatlingTest.java` に記載がある |

- 本番相当で `prod` を動かすには、PostgreSQL の DB と JWT の秘密鍵が必要である（`README.md` の「Production」）。秘密鍵は `JHIPSTER_SECURITY_AUTHENTICATION_JWT_BASE64_SECRET` に、64 バイト以上のランダムな値を Base64 でエンコードしたものを設定する。
- Docker Compose の定義は `src/main/docker/` にある（`app.yml`、`services.yml`、`postgresql.yml`、`monitoring.yml`、`sonar.yml`、`jhipster-control-center.yml`）。

## 11. 環境変数による設定の上書き

| 環境変数 | 内容 | 根拠 |
|---|---|---|
| `SPRING_DATASOURCE_*` | DB の接続設定の上書き | `README.md` の「Production」 |
| `JHIPSTER_SECURITY_AUTHENTICATION_JWT_BASE64_SECRET` | JWT の秘密鍵 | `README.md` の「Production」 |
| `SPRING_PROFILES_ACTIVE` | Spring プロファイルの指定 | `src/main/docker/app.yml` |
| `MANAGEMENT_PROMETHEUS_METRICS_EXPORT_ENABLED` | Prometheus 形式の出力の有効化 | `src/main/docker/app.yml` |
| `SPRING_LIQUIBASE_URL` | Liquibase が使う DB の接続先 | `src/main/docker/app.yml`、`src/main/docker/jib/entrypoint.sh` |

- コンテナーの入口スクリプト（`src/main/docker/jib/entrypoint.sh`）は、`SPRING_DATASOURCE_URL_FILE` のように変数名に `_FILE` を付けた環境変数で、値をファイルから読めるようにしている（Docker の secrets を想定した記述がスクリプト内にある）。
- 同じスクリプトは `JAVA_OPTS` を `java` コマンドに渡し、`JHIPSTER_SLEEP` の秒数だけ待ってから起動する。

## 12. CI

| 項目 | 内容 |
|---|---|

# モジュール構成と共通部品

> **位置づけ**：セキュリティ、設定クラス、例外処理、データアクセス、マイグレーションなどのモジュールごとの担当と、「どの部品をいつ使うか」をまとめたものである。呼び出しの流れは `主要処理フロー.md`、各レイヤーの書き方は `レイヤー別開発ガイド.md`、ログと監視は `ログ出力とモニタリング.md` を参照。
> パスは `src/main/java/io/github/jhipster/sample/` 基準、設定ファイルは `src/main/resources/` 基準で表記する。

## 2. セキュリティと認証

### 2.1 パスごとのルール

`config/SecurityConfiguration.java` の `filterChain(HttpSecurity http)` に、`authorizeHttpRequests` で上から順にルールを並べている。先に並んだルールが優先される。

| パス | 条件 | 備考 |
|---|---|---|
| `POST /api/authenticate`、`GET /api/authenticate` | `permitAll()` | ログインと認証状態の確認 |
| `/api/register` | `permitAll()` | ユーザー登録 |
| `/api/activate` | `permitAll()` | アカウントの有効化 |
| `/api/account/reset-password/init`、`/api/account/reset-password/finish` | `permitAll()` | パスワードリセット |
| `/api/admin/**` | `hasAuthority(AuthoritiesConstants.ADMIN)` | 管理者向け（`UserResource`） |
| `/api/**` | `authenticated()` | 上記以外の API はすべて認証が必要 |
| `/v3/api-docs/**` | `hasAuthority(AuthoritiesConstants.ADMIN)` | OpenAPI のドキュメント |
| `/management/health`、`/management/health/**` | `permitAll()` | ヘルスチェック（プローブ含む） |
| `/management/info` | `permitAll()` | アプリケーションの情報 |
| `/management/prometheus` | `permitAll()` | Prometheus が取得するメトリクス |
| `/management/**` | `hasAuthority(AuthoritiesConstants.ADMIN)` | 上記以外の管理エンドポイント |
| `/h2-console/**` | `permitAll()` | dev プロファイルのときだけ追加される |

### 2.2 フィルターチェーンのその他の設定

| 設定 | 内容 | コード上の位置 |
|---|---|---|
| CORS | `http.cors(withDefaults())`。設定の実体は `config/WebConfigurer#corsFilter` | `filterChain` |
| CSRF | 無効（`.csrf(csrf -> csrf.disable())`） | `filterChain` |
| セキュリティヘッダー | Content Security Policy（`jhipster.security.content-security-policy` の値）、フレーム表示は `sameOrigin`、Referrer Policy は `STRICT_ORIGIN_WHEN_CROSS_ORIGIN`、Permissions Policy を設定 | `filterChain` の `headers` |
| セッション | 使わない（`SessionCreationPolicy.STATELESS`） | `filterChain` の `sessionManagement` |
| 認証・認可の失敗 | `BearerTokenAuthenticationEntryPoint` と `BearerTokenAccessDeniedHandler` | `filterChain` の `exceptionHandling` |
| JWT | `oauth2ResourceServer(oauth2 -> oauth2.jwt(withDefaults()))` | `filterChain` |
| パスワードの保管 | `BCryptPasswordEncoder` を `PasswordEncoder` として定義 | `passwordEncoder()` |
| メソッドセキュリティ | `@EnableMethodSecurity(securedEnabled = true)` | クラスの注釈 |

### 2.3 JWT の検証と発行

`config/SecurityJwtConfiguration.java` が `JwtDecoder` と `JwtEncoder` を定義する。署名アルゴリズムは `security/SecurityUtils.JWT_ALGORITHM`（`MacAlgorithm.HS512`）。鍵は設定 `jhipster.security.authentication.jwt.base64-secret` を Base64 デコードした値である。

- この設定キーに既定値はない（`@Value("${jhipster.security.authentication.jwt.base64-secret}")`）。値がないとアプリを起動できない。
- dev はプロファイルグループで `secret-samples` を読み、サンプル値を使う。prod はサンプル値を読み込まないため、環境変数 `JHIPSTER_SECURITY_AUTHENTICATION_JWT_BASE64_SECRET` などで指定する（`README.md` の「Production」）。
- `jwtDecoder` は検証失敗の理由を `management/SecurityMetersService.java` に記録してから例外を送出する（`主要処理フロー.md` の 10 節）。
- `management/SecurityMetersService.java` には `trackTokenUnsupported()` もあるが、`SecurityJwtConfiguration` から呼んでいる箇所はない。

### 2.4 `security` パッケージのクラス

| クラス | 担当 | 主な内容と利用箇所 |
|---|---|---|
| `AuthoritiesConstants` | 権限名の定数 | `ADMIN`、`USER`、`ANONYMOUS`（いずれも `ROLE_` を含む文字列）。`SecurityConfiguration`、`UserService`、`UserResource` など |
| `SecurityUtils` | 現在の認証情報を取り出す静的ユーティリティ | 定数 `JWT_ALGORITHM`、`AUTHORITIES_CLAIM`（`auth`）、`USER_ID_CLAIM`（`userId`）。本体で呼ばれているのは `getCurrentUserLogin()` のみ（`AccountResource`、`UserService`、`SpringSecurityAuditorAware`） |
| `DomainUserDetailsService` | DB のユーザーで認証する `UserDetailsService` の実装 | Bean 名は `userDetailsService`。内部クラス `UserWithId` はユーザーの id を保持する |
| `SpringSecurityAuditorAware` | 監査項目の登録者を返す | ログイン名、取得できないときは `Constants.SYSTEM` |
| `UserNotActivatedException` | 有効化されていないユーザーの認証試行を表す | `AuthenticationException` を継承。`DomainUserDetailsService` が投げる |

- `SecurityUtils` の `getCurrentUserJWT()`、`getCurrentUserId()`、`isAuthenticated()`、`hasCurrentUserAnyOfAuthorities(String...)`、`hasCurrentUserNoneOfAuthorities(String...)`、`hasCurrentUserThisAuthority(String)` は、本体に呼び出し元がない。テストソースの `security/SecurityUtilsUnitTest.java` で検証している。

### 2.5 エンドポイントを追加するときの影響

| 追加するエンドポイントの場所 | 何も設定しなかった場合の動作 | 必要な作業 |
|---|---|---|
| `/api/...` | 認証が必要 | なし |
| `/api/admin/...` | `ROLE_ADMIN` が必要 | なし（`UserResource` はさらに `@PreAuthorize` も付けている） |
| `/api/...` を未認証で呼べるようにする | 認証が必要なまま | `filterChain` の `requestMatchers(...).permitAll()` に追加する |
| `/api`、`/management` のいずれにも入らないパス | 拒否される | `filterChain` にルールを追加する |

手順の詳細は `REST・エンティティ追加手順.md` を参照。

## 4. 例外処理

### 4.1 例外クラスの一覧

| クラス | 継承元 | 用途 | 使う場所 |
|---|---|---|---|
| `web.rest.errors.BadRequestAlertException` | `ErrorResponseException` | REST コントローラの入力チェックによる `400` | `BankAccountResource`、`LabelResource`、`OperationResource`、`AuthorityResource`、`UserResource` |
| `web.rest.errors.EmailAlreadyUsedException` | `BadRequestAlertException` | email が既に使われている（`userManagement`、`emailexists`） | `AccountResource`、`UserResource`、`ExceptionTranslator` |
| `web.rest.errors.LoginAlreadyUsedException` | `BadRequestAlertException` | ログイン名が既に使われている（`userManagement`、`userexists`） | `UserResource`、`ExceptionTranslator` |
| `web.rest.errors.InvalidPasswordException` | `ErrorResponseException` | パスワードの長さが不正なときの `400` | `AccountResource`、`ExceptionTranslator` |
| `web.rest.errors.ExceptionTranslator` | `ResponseEntityExceptionHandler` | 例外をエラー応答に変えるコントローラアドバイス（`@ControllerAdvice`） | グローバル |
| `web.rest.errors.ErrorConstants` | なし（定数） | `type` の URI（`PROBLEM_BASE_URL` 基準）とメッセージのキー | エラー応答の組み立て |
| `web.rest.errors.FieldErrorVM` | なし（値オブジェクト） | エラー応答の `fieldErrors` の要素（`objectName`、`field`、`message`） | `ExceptionTranslator` |
| `service.EmailAlreadyUsedException` | `RuntimeException` | サービスレイヤーの業務例外 | `UserService` |
| `service.UsernameAlreadyUsedException` | `RuntimeException` | サービスレイヤーの業務例外 | `UserService` |
| `service.InvalidPasswordException` | `RuntimeException` | 現在のパスワードの照合に失敗した | `UserService#changePassword` |
| `security.UserNotActivatedException` | `AuthenticationException` | 有効化されていないユーザー | `DomainUserDetailsService` |
| `AccountResource` の内部クラス `AccountResourceException` | `RuntimeException`（`@ResponseStatus` 付き） | アカウント処理の失敗（見つからないユーザーなど） | `AccountResource` のみ |

### 4.2 作法

- REST コントローラで入力チェックに失敗したときは `BadRequestAlertException(メッセージ, ENTITY_NAME, エラーキー)` を投げる。
- サービスレイヤーでは `web.rest.errors` を使わず、`service` パッケージの例外を投げる（レイヤーの依存方向の規則による）。`ExceptionTranslator` が対応するエラー応答に変換する。
- 同じ単純名の例外が `service` と `web.rest.errors` の両方にある（`EmailAlreadyUsedException`、`InvalidPasswordException`）。`import` で取り込むパッケージを間違えないこと。
- エラー応答の形式と変換の流れは `主要処理フロー.md` の 5 節を参照。

## 6. データアクセス

| 仕組み | 設定箇所 | 内容 |
|---|---|---|
| リポジトリの検索先 | `config/DatabaseConfiguration.java` | `@EnableJpaRepositories({ "io.github.jhipster.sample.repository" })` |
| スキーマの自動生成 | `config/application.yml` の `spring.jpa.hibernate.ddl-auto` | `none`。テーブルの定義は Liquibase だけが持つ |
| OSIV | `config/application.yml` の `spring.jpa.open-in-view` | `false` |
| 命名規則 | `config/application.yml` の `spring.jpa.hibernate.naming` | 物理名は `CamelCaseToUnderscoresNamingStrategy`、暗黙名は `SpringImplicitNamingStrategy` |
| バッチ | `config/application.yml` の `spring.jpa.properties.hibernate.jdbc.batch_size` など | `batch_size: 25`、`order_inserts: true`、`order_updates: true` |
| タイムゾーン | `config/application.yml` の `spring.jpa.properties.hibernate.jdbc.time_zone` など | `UTC`、`hibernate.timezone.default_storage: NORMALIZE`、`hibernate.type.preferred_instant_jdbc_type: TIMESTAMP` |
| 第 2 レベルキャッシュ | `config/application.yml` の `spring.jpa.properties.hibernate.cache.*`、`config/CacheConfiguration.java` | `use_second_level_cache: true`、`use_query_cache: false` |
| 監査 | `config/DatabaseConfiguration.java`、`domain/AbstractAuditingEntity.java` | `@EnableJpaAuditing` と `AuditingEntityListener` |
| Hibernate と Jackson | `config/JacksonHibernateConfiguration.java` | `Hibernate7Module` を Bean にする |
| H2 の TCP サーバー | `config/DatabaseConfiguration.java` の `h2TCPServer` | dev かつ `spring.h2.console.enabled=true` のとき。ポートは `server.port` に 10000 を加えた値 |
| 接続プール | `config/application-dev.yml`、`config/application-prod.yml` の `spring.datasource.hikari` | `auto-commit: false`、`poolName: Hikari` |

- タイムゾーンの扱いはテストソースの `config/timezone/HibernateTimeZoneIT.java` が各日時型について検証している。使うテーブル `jhi_date_time_wrapper` はテスト用のコンテキストでだけ作られる。
- キャッシュの対象とするエンティティは `@Cache(usage = CacheConcurrencyStrategy.READ_WRITE)` などをクラスと関連のフィールドに付けて示す。キャッシュ領域の一覧は `config/CacheConfiguration.java` の `cacheManagerCustomizer` にある。

## 7. データベースマイグレーション

| 項目 | 内容 | 根拠 |
|---|---|---|
| 実行のタイミング | アプリの起動時（既定では非同期） | `config/LiquibaseConfiguration.java`、`config/ApplicationProperties.java` |
| 親チェンジログ | `src/main/resources/config/liquibase/master.xml` | `LiquibaseConfiguration` の `setChangeLog` |
| チェンジログの形式 | XML。`config/liquibase/changelog/` に置く | `master.xml` の `<include>` |
| ファイル名 | `<yyyyMMddHHmmss>_added_entity_<エンティティ>.xml`、制約は `<yyyyMMddHHmmss>_added_entity_constraints_<エンティティ>.xml` | `config/liquibase/changelog/` の既存ファイル |
| チェンジセットの ID | `<yyyyMMddHHmmss>-1`（テーブル作成）、`<yyyyMMddHHmmss>-1-data`（サンプルデータ）、`<yyyyMMddHHmmss>-1-relations`（結合テーブル）、`<yyyyMMddHHmmss>-2`（制約）。`author` は `jhipster` | 各チェンジログ |
| DB ごとの型の差異 | `master.xml` の `<property>`（`now`、`floatType`、`datetimeType` など）で h2 と postgresql を切り替える | `master.xml` |
| 初期データ | `config/liquibase/data/` の CSV（`authority.csv`、`user.csv`、`user_authority.csv`）。区切りは `;` | `00000000000000_initial_schema.xml` の `loadData` |
| サンプルデータ | `config/liquibase/fake-data/` の CSV。`context="faker"` のチェンジセットで読み込む | `20150805124936_added_entity_Label.xml` など |
| コンテキスト | dev は `dev, faker`、prod は `prod`、テストは `test` | `config/application-dev.yml`、`config/application-prod.yml`、テスト用設定 |
| テスト専用のテーブル | `jhi_date_time_wrapper`（`context="test"`） | `00000000000000_initial_schema.xml` のチェンジセット `00000000000002` |
| 差分の生成 | `pom.xml` の `liquibase-maven-plugin` に `liquibase:diff` の設定がある（エンティティと DB の差分を `config/liquibase/changelog/${maven.build.timestamp}_changelog.xml` に出力する） | `pom.xml` の `<pluginManagement>` |

チェンジログの追加手順は `REST・エンティティ追加手順.md` を参照。

## 8. Web 共通

| クラス | 担当 | ポイント |
